This guide walks through the complete six-step workflow that Magazine Web PPT Skill runs on your behalf. By the end you will have a single `index.html` file you can open in any browser and present immediately — no build tools, no export, no server. Each step maps directly to a section in `SKILL.md`, which Claude reads before it writes a single line of HTML.

<Warning>
Always run the class pre-flight check (Step 3, sub-step 3.0) before writing any slide HTML. Missing class definitions cause entire slides to lose their styling — large headings fall back to sans-serif, stat cards collapse, and pipeline rows merge into a single line.
</Warning>

## The six-step workflow

<Steps>
  <Step title="Requirements clarification">
    Before touching any code, Claude aligns on six questions. If you have already provided a complete outline and images, you can skip to Step 2. If you only have a topic or a vague idea, Claude works through this checklist first — getting the structure wrong at this stage is expensive to fix later.

    | # | Question | Why it matters |
    |---|----------|---------------|
    | 1 | **Who is the audience? What is the setting?** (internal team / product launch / demo day / private share) | Determines language register and depth |
    | 2 | **How long is the talk?** | 15 min ≈ 10 slides, 30 min ≈ 20 slides, 45 min ≈ 25–30 slides |
    | 3 | **Do you have source material?** (docs, data, old PPT, article links) | Builds from real content rather than guessing |
    | 4 | **Do you have images? Where are they?** | Layouts 4, 5, and 10 cannot be visually validated without images |
    | 5 | **Which color theme?** | Choose from 5 presets in `references/themes.md` |
    | 6 | **Any hard constraints?** (must include X / must not include Y) | Avoids rework |

    If you do not yet have an outline, Claude uses this narrative arc template to build one:

    ```
    Hook       → 1 page   : One contrast, question, or hard data point to stop the audience
    Context    → 1-2 pages: Background, who you are, why this topic
    Core       → 3-5 pages: Main content, using Layouts 4/5/6/9/10 interleaved
    Shift      → 1 page   : Break an expectation or introduce a new point of view
    Takeaway   → 1-2 pages: Memorable line, open question, or action recommendation
    ```

    The outline, slide count plan, and theme rhythm table must all be aligned before moving to Step 2. Save the outline as `outline-v1.md` alongside the project for easy iteration.
  </Step>

  <Step title="Copy the template">
    Claude copies `assets/template.html` to your project and creates an `images/` folder next to it:

    ```bash
    mkdir -p "project/XXX/ppt/images"
    cp "<SKILL_ROOT>/assets/template.html" "project/XXX/ppt/index.html"
    ```

    `template.html` is a fully runnable file — CSS, WebGL shader, flip navigation JS, and font/icon CDN links are all pre-wired. Only the `<main id="deck">` section needs to be filled with slide content.

    **2.1 — Replace required placeholders immediately.** After copying, search for `[必填]` and replace every instance before writing any slides. The `<title>` tag ships as `[必填] 替换为 PPT 标题 · Deck Title` — leaving it in place means the browser tab will display that placeholder text during your presentation.

    | Location | Original value | Replace with |
    |----------|---------------|-------------|
    | `<title>` | `[必填] 替换为 PPT 标题 · Deck Title` | Your actual deck title (e.g., `A New Way to Work · Luke Wroblewski`) |

    **2.2 — Select a color theme.** The skill accepts only one of five curated presets. Custom hex values are not accepted — the presets protect the aesthetic.

    | # | Theme | Best for |
    |---|-------|---------|
    | 1 | Ink Classic | General use, business launches, default when unsure |
    | 2 | Indigo Porcelain | Technology, research, data, technical conferences |
    | 3 | Forest Ink | Nature, sustainability, culture, non-fiction |
    | 4 | Kraft Paper | Nostalgia, humanities, literature, independent publishing |
    | 5 | Dune | Art, design, creative work, gallery presentations |

    To apply a theme, Claude opens `references/themes.md`, finds the matching `:root` block, and replaces the six theme variables (`--ink`, `--ink-rgb`, `--paper`, `--paper-rgb`, `--paper-tint`, `--ink-tint`) at the top of the copied `template.html`. All other CSS uses `var(--...)` so no other changes are needed.
  </Step>

  <Step title="Fill in slide content">
    **3.0 — Class pre-flight check (most important step).** Before writing any slide HTML, Claude reads `assets/template.html` through to the end of the `<style>` block, then cross-references every class name used in `layouts.md`. If a class is missing from `<style>`, it gets added there — not inline on individual slides.

    Classes that must be confirmed present before starting:

    `h-hero` / `h-xl` / `h-sub` / `h-md` / `lead` / `kicker` / `meta-row` / `stat-card` / `stat-label` / `stat-nb` / `stat-unit` / `stat-note` / `pipeline-section` / `pipeline-label` / `pipeline` / `step` / `step-nb` / `step-title` / `step-desc` / `grid-2-7-5` / `grid-2-6-6` / `grid-2-8-4` / `grid-3-3` / `grid-6` / `grid-3` / `grid-4` / `frame` / `frame-img` / `img-cap` / `callout` / `callout-src` / `chrome` / `foot`

    **3.0.5 — Theme rhythm planning.** Before picking any layout, list the theme class for every slide (`hero dark` / `hero light` / `light` / `dark`) and verify the sequence follows these rules:

    - Every `<section>` must carry one of `light`, `dark`, `hero light`, or `hero dark` — never just `hero`
    - No more than two consecutive slides with the same theme class
    - Decks of 8 or more slides must include at least one `hero dark` and one `hero light`
    - The deck cannot consist entirely of `light` content slides — `dark` slides are required for visual breathing room
    - Insert one hero slide every 3–4 content slides

    **3.1 — Layout selection.** Claude does not write slide HTML from scratch. It opens `references/layouts.md` and picks from ten paste-ready `<section>` skeletons:

    | Layout | Purpose |
    |--------|---------|
    | 1. Opening cover | First slide |
    | 2. Act divider | Start of each new section |
    | 3. Data stat | Present a hard number |
    | 4. Left text / right image | Identity contrast or story |
    | 5. Image grid | Multi-image comparison or screenshot proof |
    | 6. Two-column pipeline | Workflow or process |
    | 7. Suspense / question | End of act or closing hook |
    | 8. Big quote | Serif pull-quote or takeaway |
    | 9. Before / after comparison | Old model vs. new model |
    | 10. Lead image + side text | Information-dense image and text page |

    **3.2 — Image ratio rules.** Images always use standard ratios. Never copy the original file's raw pixel dimensions.

    | Context | Recommended ratio |
    |---------|-----------------|
    | Left text / right image — main image | 16:10 or 4:3 with `max-height:56vh` |
    | Image grid (multiple images) | Fixed `height:26vh` — do not use `aspect-ratio` |
    | Small left image + right text | 1:1 or 3:2 |
    | Full-screen hero visual | 16:9 with `max-height:64vh` |
    | Lead image mixed layout | 3:2 or 3:4 |

    Images must never use `align-self:end` — they will slide to the cell bottom and be obscured by browser UI. Use `align-items:start` on the grid container instead (already set in `template.html`).
  </Step>

  <Step title="Self-check against the quality checklist">
    After all slides are written, Claude opens `references/checklist.md` and reviews every item. The checklist captures every issue found during real iterative deck builds. All P0-level rules must pass before the deck is delivered.

    The most common P0 failures to check manually:

    1. Large headings displaying in sans-serif — means the `h-hero` class was missing from `template.html` (Step 3.0 was skipped)
    2. Image grid cells expanding beyond the slide — means `aspect-ratio` was used instead of `height:Nvh`
    3. Images drifting to the bottom of their grid cell — means `align-self:end` was used instead of `align-items:start`
    4. Images using raw pixel ratios instead of standard ratios (16:10 / 4:3 / 3:2 / 1:1 / 16:9)
    5. Chinese headings longer than 5 characters without `white-space:nowrap` — causes single-character line breaks
    6. Emoji anywhere in the deck — the skill uses Lucide line icons exclusively
    7. Wrong font for a content tier — headings must be serif, body must be sans-serif, metadata must be monospace
  </Step>

  <Step title="Preview in the browser">
    Open the file directly in your browser. No local server is needed because all assets are either inlined or loaded from CDN, and images use relative paths.

    On macOS:

    ```bash
    open "project/XXX/ppt/index.html"
    ```

    Images are referenced as `images/xxx.png` relative to `index.html`. Confirm every image loads and every slide renders at the correct viewport size before presenting.
  </Step>

  <Step title="Iterate">
    After previewing, pass feedback to Claude and it adjusts the deck. Because the template CSS is heavily parameterized, the majority of visual changes are single inline style edits:

    - Font size: `font-size:Xvw`
    - Height: `height:Yvh`
    - Gap / spacing: `gap:Zvh`

    No theme variables or global CSS need to change for typical refinements. For content changes, Claude returns to the relevant layout skeleton in Step 3.1 and rewrites the affected `<section>` block.
  </Step>
</Steps>
