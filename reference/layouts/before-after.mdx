The before/after layout is for contrasting old and new approaches, before and after states, or competing paradigms. Two equal columns sit side by side: the left column represents the old model and is rendered at `opacity:.55` to signal it as the thing being replaced; the right column represents the new model at full brightness. Both columns use a left border and padding to create a blockquote-like framing.

**Default theme:** `light` (two dense text columns need a clean background for readability)

## Grid and visual treatment

The layout uses `.grid-2-6-6` for a perfect 1:1 split. The `gap:5vw 4vh` override widens the horizontal gap between columns to create a clear visual separation between the two states.

**Left column (old):** `opacity:.55` applies to the entire column div, including its kicker, heading, and bullet list. This makes the old state visually recede without removing it — the audience can still read it, but their eye is drawn to the right column first.

**Right column (new):** full opacity, same structure as the left. The contrast between 55% and 100% opacity does all the argumentative work — no color coding, icons, or labels needed beyond the kicker.

## Column structure

Both columns follow the same internal structure for visual consistency:

```
div (padding + border-left)
  .kicker           ← "Before · 旧模式" or "After · 新模式"
  h3.h-md           ← concise label for the state (≤ 5 words)
  <ul>              ← 3–5 bullet points, flex column for spacing
    <li>            ← each bullet is one concrete, parallel statement
```

## `border-left` framing

Both columns use `border-left:3px solid currentColor` to give them a blockquote-like visual frame. `currentColor` inherits the theme's ink color automatically, so the border works on both `light` and `dark` themes without any override.

Keep the bullet points parallel in structure across both columns — if the left has 4 bullets, the right should have 4 bullets. Mismatched counts make the comparison feel unbalanced.
